# Architecture Decision Records (ADRs)

Documented architectural decisions with context and rationale.

## Purpose

ADRs document important architectural decisions:
- **Context**: What problem are we solving?
- **Decision**: What did we decide?
- **Rationale**: Why did we choose this?
- **Alternatives**: What else did we consider?
- **Consequences**: What are the trade-offs?

## ADR Format

Each ADR follows a standard format:
- **Status**: Proposed | Accepted | Deprecated | Superseded
- **Date**: When decision was made
- **Deciders**: Who made the decision
- **Tags**: Categories for organization

## Best Practices

- **Document significant decisions** that affect architecture
- **Include full context** of the problem
- **Document alternatives** explicitly
- **Update status** as decisions evolve
- **Link related ADRs** when decisions depend on each other
